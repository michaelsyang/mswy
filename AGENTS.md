# AGENTS.md — mswy

Personal health dashboard. React + Vite + TypeScript SPA on Cloudflare Pages.
**Read this file before making any changes.**

## Tech Stack

- React 19 + TypeScript (strict) + Vite 6
- Tanstack Query (data fetching) + React Router 7
- Cloudflare Pages (hosting + CDN)
- npm only — do not use pnpm or yarn

## Commands

```bash
npm install          # install deps
npm run dev          # dev server at localhost:5173
npm run build        # tsc -b && vite build → dist/
npm run preview      # preview production build locally
npx tsc --noEmit     # typecheck only
npm run lint         # eslint
npm run format       # prettier (writes to src/)
```

## Deployment (CRITICAL)

Deploy is via **wrangler CLI**, not git push:

```bash
npm run build && npx wrangler pages deploy dist --project-name=mswy --branch=main --commit-dirty=true
```

- `dist/` is gitignored — you **must build first**
- Production branch is `main` — use `--branch=main`, **never** `--branch=production`
- `--branch=production` creates a **preview deployment** that won't reach mswy.xyz
- Wrangler auth is handled externally (env var `CLOUDFLARE_API_TOKEN`) — do not configure auth in-repo
- After deploy, verify headers: `curl -sI https://mswy.xyz/health | grep -i cache-control`

### CI vs manual deploy

GitHub Actions (`.github/workflows/deploy.yml`) also deploys on push to main/staging, but **ignores `public/data.json` changes** (paths-ignore). In practice, code pushes trigger CI deploys and data refreshes are deployed manually via wrangler. If you deploy manually after a code push, the CI deploy may race yours — push code, let CI deploy, then separately push data + deploy data via wrangler.

## Data Pipeline

- `public/data.json` is generated by an **external health data sync pipeline**
- Do not manually edit `data.json` — it will be overwritten
- The app fetches from `/data.json` (absolute path at site root)
- The Python backend can emit `baseline: null` for metrics without historical data — TS types must allow this (see Gotchas)

## Code Conventions

- Functional components with hooks only — no class components
- Named exports preferred
- All data fields that can be null must be typed `T | null` — the backend emits nulls
- Guard against null/undefined before accessing nested properties
- SVG charts are hand-rolled (no charting library) — see `src/lib/svg-utils.ts`
- Health metric colors: HRV higher=better (green), RHR lower=better (green inverted) — see `health-utils.ts`

## Gotchas (Learned from Past Bugs)

1. **Cache headers**: HTML must have `no-store` in `public/_headers`, not just `max-age=0`. Without `no-store`, Chrome falls back to heuristic caching and serves stale HTML indefinitely. The `_headers` file must include:
   ```
   /*
     Cache-Control: no-store, no-cache, must-revalidate
   /assets/*
     Cache-Control: public, max-age=31536000, immutable
   ```
2. **Data fetch URL**: Always fetch `/data.json` (absolute path). Never use `/health-v3/data.json` or other versioned paths — those are leftovers from the old vanilla JS project.
3. **Null baseline crash**: The backend emits `baseline: null` for metrics like `sleep_quality` that have no historical baseline. TS types must use `baseline: number | null`. Always null-check before calling `.toFixed()` or rendering.
4. **Deploy branch**: Use `--branch=main` only. `--branch=production` creates a preview deployment.
5. **No runtime schema validation**: `useHealthData.ts` casts `as HealthData` without validation. Any backend schema drift becomes a render crash. If adding new data fields, update `types.ts` and handle nulls.

## Boundaries

### ✅ Always
- Run `npm run build` before deploying
- Verify the deploy URL in wrangler output
- Null-check API responses before accessing properties
- Check `public/_headers` when modifying caching behavior
- Commit changes after deploying (keep working tree clean)

### ⚠️ Ask First
- Adding new npm dependencies
- Changing `vite.config.ts`, `tsconfig.json`
- Modifying `public/_redirects` or `public/_headers`
- Changing the data fetch URL or `DATA_URLS` array

### 🚫 Never
- Deploy with `--branch=production`
- Manually edit `public/data.json`
- Use versioned data URLs (`/health-v3/data.json`)
- Commit `dist/`, `.env`, secrets, or credentials
- Hardcode API tokens, account IDs, zone IDs, or server paths
- Reference internal infrastructure (Hermes config, cron jobs, pipeline paths)
- Force push to main

## Security

This is a **public repository** (github.com/michaelsyang/mswy).

- Never commit secrets, tokens, or credentials
- Deployment auth is external — do not configure wrangler auth in-repo
- Reference env vars by name only (e.g., `CLOUDFLARE_API_TOKEN`), never by value
